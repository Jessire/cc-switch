# 状态协调与真实验证约定

本目录下的重要任务统一采用 reconciliation loop:

1. **Desired state**: 先写清最终应达到的状态, 例如“标准 Release EXE 正在运行”, “配置重启后仍保留”, “签到结果为成功或明确需要人工处理”。
2. **Observe**: 从目标侧读取真实状态, 不用构建输出、HTTP 200 或脚本退出码代替。
3. **Diff**: 明确期望与实际的差异。
4. **Reconcile**: 只修复差异, 操作必须可重复执行, 不覆盖用户数据。
5. **Verify**: 再次读取目标侧状态并记录证据。

## 统一验收规则

- 文件: 路径、版本、大小、SHA256。
- 进程: PID、可执行文件绝对路径、启动参数、窗口状态。
- 配置: 持久化源、生成的 live 文件、重启后回读。
- 网络: 不以 `/models` 或 HTTP 200 作为业务成功; 至少执行一次真实目标链路。
- 自动化: 记录每次运行的状态、阶段、错误类别和时间; 成功、重复成功、需要人工、超时、上游错误必须区分。
- 失败重试: 先重新 observe, 再按差异修复; 禁止盲目重复相同动作。

## 项目落点

- `cc-switch`: `scripts/verify-release-reconciliation.ps1` 检查 Release 产物与运行进程, 不结束任何进程。
- `lol-auto`: `lol_auto.py health` 检查校准和安全配置, `run` 写入脱敏的运行状态, 不保存账号或密码。
- ScriptCat/网页脚本: 每次运行应把“页面 helper 是否实际注入”和“后台协调是否完成”作为独立状态, 不能把后台任务成功等同于页面动作成功。

## 不可伪造的完成条件

只有目标侧回读通过才报告“完成”。静态检查、构建成功、脚本退出码为 0 只能作为中间证据。
